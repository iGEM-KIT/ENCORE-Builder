 ENCORE Builder — PROJECT TODO
 Stand: 2026-09-28

Dieses Dokument listet die offenen Punkte des Projekts. Die vorherige Fassung
(Stand 2026-07-16) beschrieb eine geplante JS-Engine unter
server/services/goldenGate/ — die gibt es nicht mehr, die gesamte Design-Logik
ist inzwischen in Python (Biologik/) gebaut und fertig angebunden. Diese
Fassung beschreibt den TATSAECHLICHEN Stand.


-------------------------------------------------------------------------------
 0. AKTUELLE ARCHITEKTUR (zur Orientierung)
-------------------------------------------------------------------------------
Design-Logik komplett in Python:  Biologik/level0_design/
  - data.py         Libraries + Golden-Gate-Konstanten (Single Source of Truth)
  - sequence.py      DNA-Helfer + Cargo-Validierung (Stopcodon-Erkennung)
  - design.py        Engine: Level 0/1/2, Slots (NCS/Linker/Marker/TP/eigene
                      Sequenz), Plate-Plan, Order-Liste, GenBank-Export
  - genbank_writer.py GenBank-Flatfile-Schreiber (keine externe Abhaengigkeit)
  - mrna_dimer.py    Optionaler mRNA-Selbstfaltungs-/Dimer-Check (ViennaRNA)
  - cli.py           JSON-stdin/stdout-Adapter (design/libraries/validate)
Primer-Thermodynamik: Biologik/primer_design/ (primer3-py, mit Wallace-Fallback)

Bruecke Node -> Python:  server/utils/biologik.js (spawnt cli.py pro Request,
sucht Interpreter in der Reihenfolge BIOLOGIK_PYTHON / .venv / PATH)

API-Endpunkte (Nuxt/Nitro), alle duenne Wrapper um runBiologik():
  - GET  /api/libraries
  - POST /api/cargo/validate   (kind: cargo | shell | part)
  - POST /api/design

Frontend: KEINE Vue-Komponenten (app/ ist absichtlich leeres Nuxt-Geruest).
Die eigentliche UI ist statisches HTML/CSS/JS, von Nuxt nur ausgeliefert
(nuxt.config.ts -> nitro.publicAssets):
  - frontend/index.html              Der Builder (Level 0-2, Cargo-/NC-Site
                                      mit frei konfigurierbaren Slots, Promoter)
  - encapsulin_selector/             Separates Filter-Tool, teilt sich Header/
                                      Dark-Mode/Navigation mit dem Builder
window.ENCORE_API in index.html verbindet zum Backend; ohne erreichbaren
Server rechnet die Seite inline weiter (Wallace-Tm, keine Slot-Sequenz-Checks).

 6. BIOSECURITY SCREENING (COMMEC) — steht, end-to-end verifiziert
-------------------------------------------------------------------------------
Vor Schritt 4 wird jede selbst eingegebene Sequenz automatisch per COMMEC
("Common Mechanism", IBBIS) gescreent (server/utils/commec.js, server/api/
cargo/screen.post.js, commec-service/). Der commec-Container startet seit
2026-09-30 standardmaessig mit `docker compose up` (kein Opt-in-Profil mehr,
siehe docker-compose.yml) — bewusste Entscheidung, damit das Screening im
Normalfall nicht uebersprungen wird. Siehe README.md "Biosicherheits-Screening
ist immer dabei". Echte Unumgehbarkeit ist bei selbst gehosteter, quelloffener
Software ohnehin nicht erreichbar; das ist die ehrliche Standardeinstellung,
kein Manipulationsschutz.

[x] commec-service/ wurde real gebaut (`docker compose --profile biosecurity
    build commec`, commec 1.0.4) und end-to-end getestet: echter Container,
    echter `commec setup`-Lauf (Biorisk+Low-concern, ~1.2GB), echter
    `commec screen`-Aufruf, echtes Frontend-Warn-Modal. Positivtest mit einer
    aus UniProt bezogenen Conotoxin-Sequenz (Q9BPJ4) korrekt als "Flag"
    erkannt und im UI blockiert.
[x] Die urspruengliche Annahme "40GB Datenbank" war falsch — die echte
    COMMEC-CLI (1.0.4) bietet nur "Biorisk+Low-concern" (~1.2GB) oder volle
    Protein-NR/Nukleotid-NT-Taxonomiedatenbanken (~530GB / ~580GB, zusammen
    >1TB). Bewusst nur die kuratierte kleine Variante eingerichtet (siehe
    commec-service/Dockerfile fuer die exakte, getestete Antwortsequenz an
    das interaktive `commec setup`).
[x] Ohne Taxonomie-Datenbanken liefert commec fuer JEDE Sequenz ohne
    Biorisk-Treffer "screen_status: Warning" (auch fuer harmlose Gene wie
    GFP) — das Frontend (biosecEffectiveStatus() in frontend/index.html)
    wertet deshalb gezielt das `biorisk`-Feld aus, nicht den generischen
    Gesamtstatus. Siehe commec-service/README.md fuer die Begruendung.
[x] Statusanzeige im Header (naeben Dark-Mode-Button) zeigt live, ob der
    COMMEC-Container erreichbar ist (server/api/cargo/commec-status.get.js,
    refreshCommecStatus() im Frontend, alle 30s aktualisiert).
[ ] Aktuell wird nur der Cargo/eigene-Sequenz-Text gescreent, nicht die
    fertig zusammengesetzten Level-1/2-Konstrukte (Fusion mit TP/Linker/NCS).
    Falls gewuenscht: auch die assemblierte Sequenz zusaetzlich screenen.
[ ] Falls spaeter echte Taxonomie-Abdeckung gewuenscht ist: Protein-NR oder
    Nukleotid-NT-Datenbank ergaenzen (grosser Umbau, siehe commec-service/
    README.md "Datenbankumfang") und COMMEC_SKIP_TAXONOMY=false setzen.
