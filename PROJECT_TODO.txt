 ENCORE Builder: PROJECT TODO
 As of: 2026-09-28

This document lists the open items of the project. The previous version
(as of 2026-07-16) described a planned JS engine under
server/services/goldenGate/. That no longer exists; the whole design logic
has since been built in Python (Biologik/) and is fully connected. This
version describes the ACTUAL state.


-------------------------------------------------------------------------------
 0. CURRENT ARCHITECTURE (for orientation)
-------------------------------------------------------------------------------
Design logic entirely in Python:  Biologik/level0_design/
  - data.py         libraries + Golden Gate constants (single source of truth)
  - sequence.py      DNA helpers + cargo validation (stop codon detection)
                      (DNA or amino acids as input)
  - codon.py         codon optimization for S. cerevisiae (own sequences, without
                      BsaI/BbsI sites), back-translation of proteins
  - design.py        orchestration: design_construct (inputs -> Level 0/1/2),
                      build_genbank; the subtasks live in
  - slots.py         assignment of the modules (NCS/linker/marker/TP/own sequence)
  - user_codons.py   codon optimization of the user inputs within the design
  - constructs.py    Level 0 construct per module (adapter, plasmid, primers, oligos)
  - adapters.py      insert into overhang adapters, neighbour context, rotating the cargo site
  - cloning.py       BbsI cloning into the Level 0 backbone
  - primers.py       cargo primers (Level 1) and Level 0 primers, PCR product
  - oligos.py        oligo pairs for parts below 150 bp
  - assembly.py      Level 1/2 assembly (BsaI/BbsI)
  - genbank_writer.py GenBank flat file writer (no external dependency)
  - cli.py           JSON stdin/stdout adapter (design/libraries/validate/to_dna)
Primer thermodynamics: Biologik/primer_design/ (primer3-py, with Wallace fallback)

Conventions:
  - Everything the user sees (UI, messages, GenBank texts) and all code comments,
    docstrings and docs: English, without dashes used as punctuation; hyphens only
    between two words.
  - The browser caches (encore.libs/val/design) carry an id derived from the script of the page
    (BUILD_ID in index.html); a changed script starts with empty caches, no bumping by hand.
  - The UI needs the server (no offline model any more); without it the page shows a notice.

Bridge Node -> Python:  server/utils/biologik.js (spawns cli.py per request,
looks for an interpreter in the order BIOLOGIK_PYTHON / .venv / PATH)

API endpoints (Nuxt/Nitro), all thin wrappers around runBiologik():
  - GET  /api/libraries
  - POST /api/cargo/validate   (kind: cargo | shell | part)
  - POST /api/cargo/screen
  - POST /api/design

Frontend: NO Vue components (app/ is deliberately an empty Nuxt scaffold).
The actual UI is static HTML/CSS/JS, only served by Nuxt
(nuxt.config.ts -> nitro.publicAssets):
  - frontend/index.html              the builder (Level 0-2, cargo/NC site
                                      with freely configurable slots, promoter)
  - frontend/guide.html              the guide behind "Before you start"
  - encapsulin_selector/             separate filter tool, shares header/
                                      dark mode/navigation with the builder
window.ENCORE_API in index.html connects to the backend; without a reachable
server the page shows a notice (the builder cannot work without it).

 6. BIOSECURITY SCREENING (COMMEC): in place, verified end to end
-------------------------------------------------------------------------------
Before step 4, every sequence entered by the user is automatically screened by COMMEC
("Common Mechanism", IBBIS) (server/utils/commec.js, server/api/
cargo/screen.post.js, commec-service/). Since 2026-09-30 the commec container
starts by default with `docker compose up` (no opt-in profile any more,
see docker-compose.yml); a deliberate decision so that the screening is
not skipped in the normal case. See README.md "Biosecurity screening is
always included". Real unavoidability cannot be achieved with self-hosted,
open source software anyway; this is the honest default,
not a tamper protection.

[x] commec-service/ was really built (`docker compose --profile biosecurity
    build commec`, commec 1.0.4) and tested end to end: real container,
    real `commec setup` run (biorisk + low-concern, ~1.2GB), real
    `commec screen` call, real frontend warning modal. Positive test with a
    conotoxin sequence obtained from UniProt (Q9BPJ4) correctly detected as "Flag"
    and blocked in the UI.
[x] The original assumption "40GB database" was wrong; the real
    COMMEC CLI (1.0.4) only offers "biorisk + low-concern" (~1.2GB) or full
    protein NR/nucleotide NT taxonomy databases (~530GB / ~580GB, together
    >1TB). Deliberately only the small curated variant was set up (see
    commec-service/Dockerfile for the exact, tested answer sequence to
    the interactive `commec setup`).
[x] Without taxonomy databases commec returns "screen_status: Warning" for EVERY sequence without a
    biorisk hit (also for harmless genes such as
    GFP); the frontend (biosecEffectiveStatus() in frontend/index.html)
    therefore evaluates the `biorisk` field specifically, not the generic
    overall status. See commec-service/README.md for the rationale.
[x] Status display in the header (next to the dark mode button) shows live whether the
    COMMEC container is reachable (server/api/cargo/commec-status.get.js,
    refreshCommecStatus() in the frontend, refreshed every 30s).
[x] Amino acid inputs are screened as well: the server back-translates them to DNA
    (cli.py to_dna) before they go to commec.
[ ] Currently only the cargo/own sequence text is screened, not the
    fully assembled Level 1/2 constructs (fusion with TP/linker/NCS).
    If wanted: also screen the assembled sequence additionally.
[ ] If real taxonomy coverage is wanted later: add the protein NR or
    nucleotide NT database (big rework, see commec-service/
    README.md "Database scope") and set COMMEC_SKIP_TAXONOMY=false.

 8. GOLDEN GATE SIMULATION (planned, not started yet)
-------------------------------------------------------------------------------
Now that all three backbones (Level 0/1/2) AND their real BsaI/BbsI
recognition sites/acceptor overhangs are available, a real restriction/
ligation simulation would be possible, not just concatenating through already known
overhang constants:

[x] Level 0 inserts from the real plasmids (parts/level0_inserts/, 37 parts from "Level 0.gb" + "0.2L4.gb" + "Level 0
    constructs.xlsx"): only the part sequence, without overhangs/spacers; site/slot from overhang or orientation, stock status from
    the glycerol column; the dropdowns only offer parts at their site/slot. Noticed during the import (to be checked):
      - 0.5 TP-TmSt (Lvl0.5_a_026): 28 nt, not divisible by 3 -> frameshift in the reading frame
      - 0.3 MVP: plasmid has only 1 nt before the ATG and lies on the sense strand (the other cargos antisense);
        0.3 CiVCPO: plasmid has no frame spacer at all
      - cargos NlucP and MVP end in a stop codon (not fusion capable: the builder rejects them as cargo);
        the shells E-Tm/Qt/Mx/Mxpe also end in a stop codon (no C-terminal fusion partner possible)
      - 0.4NCS* (Lvl0.4_a_022) is in the file twice (also as "0.4NCSrc") and has the same insert as Lvl0.4_a_021,
        only with the spacer on the other side; 0.4NCSrc (a_021) is stored on the sense strand despite "rc"
      - E-Mxpe is stored as a shell, but there is no nanocompartment entry in data.py yet (T number/diameter/TP missing)
      - the plasmids put the frame spacer (2 nt, partly AT/TA/TT/AA depending on the part) on the 5' side of the ORF (for cargo parts
        at the right end of the top strand); the software always puts GC directly before the insert
[x] Reading frame: every adapter carries a 2-nt frame spacer (GC) directly before the insert (parts/type_overhangs/,
    field `frame_spacer`). Overhang (4) + spacer (2) = 6 nt between two fused parts, so the ORF stays in frame across
    all seams (Level 0 -> 1 -> 2, sense and antisense module). Open/to be clarified: whether the real toolkit parts
    already encode their overhang bases themselves (then the spacer would be doubled); part sequences are still missing in the DB.
[x] Simple stage: concatenate parts through the overhangs of the Type adapters (parts/type_overhangs/);
    done in assembly.py: Level 0 -> 1 by BsaI (5 fragments over ACAT|TATG|TTCT|ATCC|TGGC|TTGT
    between NLvl1/CLvl1 of pAGM1311), Level 1 -> 2 by BbsI (cargo module CCAA..CGTT, promoter CGTT..TGAT,
    NC module TGAT..AATG between BbLvl2N/BbLvl2C of pESC-HIS). The tests "digest" the plasmids again (BsaI from
    the Level 0, BbsI from the Level 1 plasmids) and check that the same sequence comes out again. Open:
    the promoter GAL1-10 still has no real sequence (placeholder), nor do TP/linker/NCS/shell; in pESC-HIS
    a BsaI site remains in AmpR (Level 2 uses BbsI, so uncritical).
[ ] Full stage: search for BsaI (GGTCTC)/BbsI (GAAGAC) recognition sites in the
    real sequences, apply the cut offset per enzyme, compute the
